# MVP 2 — 대기·좌석 등록 규칙

이 문서는 대화에서 합의한 MVP 2 범위를 정리한 기획 문서다. 제품 구현 완료를 의미하지 않는다.

## 목적과 범위

- MVP 1: 동가가 휴대폰으로 AMOS REXX 3의 7세그 점수를 자동등록하며 닉네임은 수동 입력한다.
- MVP 2: 온라인 대기, 직원의 현장 확인, 선착순 선정, 테이블별 네 좌석 등록과 게임 세션을 관리한다.
- MVP 1의 수동 닉네임으로 대기자를 식별하지 않는다. 점수 결과와 MVP 2 세션의 구체적인 연동 방식은 추후 정의한다.

## 확정 규칙

1. 매장 공통 QR·링크로 매장 밖에서도 대기 등록할 수 있다. 회원은 계정, 비회원은 닉네임으로 등록한다.
2. 서버가 등록 순번을 부여한다. 동시 등록은 서버에서 순서를 확정한다. 시각 기반 우선순위와 추첨은 사용하지 않는다.
3. 직원이 현장 도착 여부를 관리한다. 도착 여부 변경은 등록 순번을 바꾸지 않는다.
4. 현장에 있는 대기자 중 순번이 빠른 네 명을 새 탁 멤버로 선정한다. 미도착자는 건너뛰되 순번을 유지한다.
5. 재접속·새로고침은 기존 대기 순번을 유지한다. 대기 취소 후 재등록은 새 순번을 받는다.
6. 테이블의 동·남·서·북 고정 좌석에 QR 네 개를 붙인다. 이 표시는 게임 중 바뀌는 자풍과 구분한다.
7. 첫 좌석 등록으로 등록 중 세션을 만들고, 네 좌석 등록 완료 시 활성화한다. 테이블당 미종료 세션은 하나다.
8. 좌석은 가장 최근에 등록을 완료한 계정·닉네임을 반영한다. QR 페이지를 열기만 한 것은 등록으로 처리하지 않는다.
9. 선정 명단과 실제 착석 명단의 차이를 허용한다. 운영 안내로 관리한다.
10. 네 좌석 등록 완료 시 실제 참여자를 대기열에서 제외한다. 선정됐지만 착석하지 않은 사람은 대기에 남는다.
11. 결과 저장 성공 시 당시 참여자와 결과를 보존하고 활성 세션을 종료한다. 현재 테이블은 비워지지만 과거 기록은 남는다.
12. 저장 실패 시 세션을 유지한다. 종료된 세션에 같은 결과를 재제출해도 중복 기록하지 않는다.
13. 게임을 마친 사람은 다시 대기 등록해 새 순번을 받는다. 자동 재대기는 하지 않는다.
14. 활성 테이블 수는 네 좌석 등록 완료 후 결과 저장 전인 테이블 수다. 결과 저장과 다음 게임 재등록 사이에 감소하는 것은 정상이다. 실제 착석 인원·재실 인원과 동일한 지표는 아니다.

## 필요한 화면과 기능

- 이용자: 대기 등록, 내 순번·현장 확인 상태 조회, 대기 취소, 좌석 등록, 게임 후 재대기.
- 직원: 대기 명단, 현장 여부 변경, 현장 대기 순서에 따른 네 명 선정, 선정·실제 착석 명단 비교, 테이블별 등록 상태·활성 수 확인.
- 시스템: 안정적인 대기자 식별, 순번 발급, 좌석 최신 등록 처리, 네 좌석 완료 시 대기 제외, 결과 저장 성공에 따른 종료와 중복 방지.

## 추가 결정 필요

- 직원이 선정을 실행할지, 빈 탁 발생 시 자동 제안할지.
- 선정 또는 일부 좌석 등록 중인 사람을 다른 탁의 선정에서 잠시 제외할지.
- 활성화 후 좌석 교체 시 기존 참여자의 대기 복원과 새 참여자의 대기 제외 처리. 최신 좌석 등록 우선 원칙은 확정이지만 대기열 정합성 처리는 미정이다.
- 일부만 등록한 세션의 취소·정리 권한, 부재·영업 종료 시 정리 방식.
- 비회원의 다른 브라우저·기기 사용 및 중복 등록에 대한 식별·복구 방식.
- MVP 1의 점수 결과를 어떤 세션에 연결해 종료할지에 대한 구체적 인터페이스.

## 예시

등록 순번 101 A(미도착), 102 B(현장), 103 C(현장), 104 D(현장), 105 E(현장)이면 B·C·D·E를 선정한다. A가 다음 선정 전에 도착하면 101을 유지하므로 우선한다. B·C·D·E가 게임 후 다시 대기하면 그때 새 순번을 받는다.
