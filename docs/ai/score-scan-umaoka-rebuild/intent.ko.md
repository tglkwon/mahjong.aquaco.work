## 문제와 근거
1. `ScorePhotoInputPage.tsx`는 현재 구형 기본 `Table`만 렌더링하고 있어 대회용 우마/오카 순위 계산, 동점자 처리 규칙(`split`/`seatOrder`), 4인 초과 플레이어 풀 관리, 촌보 페널티 처리, 압축 `#d=` 게임 기록 저장 등이 지원되지 않습니다.
2. 기존 라우트 `/set_score_photo`는 정적 사진 업로드를 연상시켜, MVP 1.3 / 1.4 엔진의 0.2~0.3s 실시간 비디오 스트림 스캔 본질과 부합하지 않습니다.
3. 실제 대부분의 리치 마작 대탁은 우마와 오카를 필수로 적용하므로, 일반 점수표(`/set_score`)와 우마·오카 점수표(`/set_score_umaoka`) 사이의 UX 단절을 해소할 통일된 워크플로우가 필요합니다.
4. 현장 테스트 중 개발자는 `mobile-drop` 연동 및 다양한 작탁 기종(Rexx 3, JP-EX, JP-Color 등)의 데이터셋 수집이 필요하지만, 일반 서비스 이용자에게 복잡한 PC 전송 브리지 제어판이나 PIN 입력창이 노출되어서는 안 됩니다.
5. 수동 사진 촬영 버튼(`📷 점수판 촬영하기`)은 슬라이딩 윈도우 기반 실시간 스캔에 비해 느리고 불편하여 불필요한 UI 노이즈를 만듭니다.

## 원하는 결과
1. 점수 인식 페이지를 우마·오카 계산 시스템 기반으로 전면 리빌딩하여, 인식된 원점수가 4개 좌석(동, 남, 서, 북)에 매핑되고 우마/오카 순위 점수가 즉시 계산되어 세션에 기록되도록 구현합니다.
2. 기존 `/set_score_photo` 라우트를 서비스용 `/scan_score` 및 테스트용 `/test_scan`으로 개편하고, 기존 주소 접속 시 `/scan_score`로 안전하게 리다이렉트합니다.
3. 좌석 배정 -> 실시간 스캔 -> 즉시 합의 캡처 -> 점수 배정 확인 -> 원터치 기록 및 공유 URL 복사로 이어지는 매끄러운 유저 워크플로우를 완성합니다.
4. 서비스 페이지(`/scan_score`: PC 전송 제어 숨김)와 테스트 페이지(`/test_scan`: PC 전송 브리지 및 기종 선택기 탑재)를 명확히 분리합니다.
5. 수동 사진 촬영 파일 입력 및 버튼을 제거하고, 실시간 비디오 스캔을 메인으로, 비상시 직접 수동 입력을 Fallback으로 제공합니다.

- 클라이언트 브라우저 내 인메모리 처리 원칙 유지.
- 기존 `#d=` 및 구형 `#data=` 공유 URL과의 엄격한 하위 호환성 유지.
- Windows 환경 단일 셸 PowerShell 실행 원칙 준수.

## 수용 신호
1. 실시간 스캔 결과가 우마·오카 점수 체계에 자동으로 반영되어 순위 점수가 정확히 계산됨.
2. 라우트 `/scan_score` 페이지에서 PC 전송 제어판이 노출되지 않고 깨끗한 사용자 UI가 제공됨.
3. 라우트 `/test_scan` 페이지에서 PC 전송 제어판 및 기종 선택기(Rexx 3, JP-EX, JP-Color)가 정상 작동함.
4. `/set_score_photo` 접속 시 `/scan_score`로 자연스럽게 리다이렉트됨.
5. 수동 사진 촬영 버튼 및 input 요소가 UI에서 완전히 제거됨.
6. 모든 자동화 테스트 통과 및 프로덕션 빌드 성공.

## 가정과 미해결 질문
- 프로덕션 라우트는 `/scan_score`, 테스트 라우트는 `/test_scan`으로 설정.
- 기존 URL 리다이렉트를 통해 기존 링크 및 북마크가 손상되지 않도록 보장.

## 결정 사항
- 점수 스캔 페이지를 완전한 우마·오카 계산 파이프라인 기반으로 리빌딩 채택.
- 전용 라우트 및 컴포넌트 속성을 통한 서비스 페이지와 테스트 페이지의 깔끔한 분리.
