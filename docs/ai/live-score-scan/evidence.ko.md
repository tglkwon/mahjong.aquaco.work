## E2E 증거
390×844 Edge/Chromium 모바일 에뮬레이션에서 `research-data/rex 3/inspection/browser-sample-h264.mp4`를 사용했다. 이는 `PXL_20260902_054136311.mp4`의 기존 H264 파생본이다. 테스트 전용 `getUserMedia` 주입과 `video.captureStream`으로 실제 프레임을 공급했고 실제 픽셀 인식기는 모킹하지 않았다. 제품 디버그 API는 추가하지 않았다.

증거: `docs/ai/live-score-scan/live-scan-browser-results.json`, `docs/ai/live-score-scan/live-scan-auto-capture.png`, `docs/ai/live-score-scan/live-scan-record-shared.png`, `docs/ai/live-score-scan/live-scan-total-mismatch.png`. 브라우저 JSON을 독립적으로 읽었으며 주 에이전트가 캡처를 육안 확인했다. 캡처·합계 불일치 화면에 가로 넘침이 없었다.

후보 102 / 0266 / 0606 / 0026에서 스냅샷 한 번 후 트랙이 종료됐다. 사람 확인 전 기록은 없었다. 한 자리 이동 후 플레이어 순서의 기록·공유 점수는 2600 / 10200 / 26600 / 60600이었다. 네 번 이동하면 원래 배정으로 복귀했고 반복 확인으로 중복이 생기지 않았다. 합계가 틀리면 5초 동안 캡처하지 않았다. 권한 거부 시 수동 복구, 명시적 중지, 늦은 권한 응답 정리를 통과했다. 페이지 오류·업로드 모두 0건이며 로컬 영상 GET 3건은 테스트 도구의 읽기였다.

## 리뷰 발견 사항과 해결
독립 리뷰에서 낮은 심각도 문제 하나를 발견했다. 카메라 미지원 오류가 동기적으로 발생하면 오래된 종료 함수가 남아 나중에 복구 메시지를 덮을 수 있었다. 현재 세션 토큰 가드와 회귀 테스트로 해결했다. 후속 리뷰에 차단 사항은 없었다. 기본 프레임 콜백, 재생 대기 중 취소, 시간 초과·늦은 스트림, 음소거, 다른 합계 설정, 무효 단위·플레이어, 페이지 숨김·해제 검증을 보강했다.
