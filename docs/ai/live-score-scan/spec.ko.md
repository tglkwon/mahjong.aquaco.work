## 요약
모바일 실시간 카메라로 안정된 검토 초안을 자동 캡처한다. 게임 기록은 자동으로 확정하지 않는다.

## 기능 요구사항
- REQ-001 must: 사용자 시작 동작으로 오디오 없이 후면 우선 카메라를 연다. 캡처, 취소, 페이지 숨김, 오류, 해제 시 현재 및 늦게 도착한 스트림을 정리한다. 사진·수동 입력 대안을 유지한다.
- REQ-002 must: 초당 최대 다섯 새 프레임을 읽는다. 최소 1000 ms 동안 동일한 네 점수가 다섯 번 이상 관측되고 단위, 서로 다른 플레이어, 설정 합계(기본 100000)를 충족해야 캡처한다. 무효·변경 값은 연속 판정을 초기화하고 오래된 프레임에 의한 진행과 한 세션 내 중복 캡처를 막는다.
- REQ-003 must: 진행 상태를 표시하고 로컬 프레임을 정확히 한 번 캡처한 뒤 카메라를 종료하고 편집 가능한 검토 화면을 제공한다. 동가 기준 배정, 한 자리 이동, 편집 시 확인 초기화, 사람의 명시적 기록 확정을 유지한다. 재스캔은 명시적으로 시작한다.
- REQ-004 must: 기존 실제 REXX 3 영상 파생본을 테스트 전용 가상 카메라 입력으로 사용해 인식기부터 검토 화면까지 브라우저 통합 검증한다. 제품 디버그 API는 추가하지 않는다. 무효·불안정 관측, 취소, 중복, 배정 이동을 검증한다.

## 비기능 요구사항
기기 내 처리와 제한된 프레임 샘플링을 유지한다. 모바일 화면에서 사용할 수 있어야 한다. 실기기 성능과 정확도는 연기하며 데스크톱 결과로 추정하지 않는다.

## 사용자 경험과 흐름
스캔 시작 → 권한 → 페이지 내 카메라와 인식 진행 → 안정 결과 자동 캡처 → 카메라 종료 및 초안 편집 → 배정 확인·이동 → 체크박스와 명시적 기록. 권한 거부와 미지원 환경은 복구와 대안을 안내한다. 취소하면 해당 세션 초안 없이 대기 상태로 돌아간다.

## 아키텍처와 인터페이스
안정 판정은 순수하고 테스트 가능한 상태 기계로 분리한다. 미디어 획득, 새 프레임 스케줄링, 트랙 정리, 취소 세대 처리는 인식과 분리한다. REXX 3 픽셀 인식기 및 기존 상위 검토·확정 계약을 재사용한다. 테스트 주입은 브라우저 테스트 설정에만 둔다.

## 데이터와 마이그레이션
적용 없음: 서버 스키마, 영상 영구 저장, 데이터베이스 마이그레이션이 없다. 기존 점수 초안과 기록 형식을 유지한다.

## 실패 모드와 경계 사례
권한 거부, API 부재, 장치 불가, 재생·픽셀 읽기 오류, 권한 대기 중 취소, 정지·오래된 프레임, 합계 오류, 점수 변화, 안정 결과 반복, 숨김 탭, 해제를 처리한다. 합계 일치만으로 개별 점수 정확성이 입증되지는 않는다.

## 보안, 개인정보, 권한
보안 출처에서 브라우저 카메라 권한을 사용한다. 마이크 권한, 이미지 업로드, 배포 코드의 디버그 훅을 추가하지 않는다. 미디어 트랙을 신속히 종료한다.

## 관측성과 운영
의미 있는 스캔 상태와 복구 가능한 오류를 사용자에게 표시한다. 카메라 업로드 없이 로컬 테스트 증거를 보관한다. 배포와 터널은 활성화하지 않는다.

## 테스트 전략
안정 판정과 수명주기의 실패 테스트를 먼저 작성한다. 검토 UI, 이동, 확인, 초기화를 테스트한다. 실제 영상 파생 스트림으로 브라우저를 검증한다. 전체 테스트, 타입 검사, 빌드, 독립 리뷰를 수행하고 정확한 결과를 증거에 기록한다.

## 수용 기준
- AC-001: 늦은 권한 응답 정리를 포함한 수명주기와 대안 테스트로 REQ-001을 입증한다.
- AC-002: 결정적 상태 테스트로 REQ-002의 임계값, 새 프레임 조건, 무효 초기화, 단위·플레이어 검증, 합계 설정, 단일 캡처를 입증한다.
- AC-003: UI 테스트로 REQ-003의 사람 확인, 배정 순환, 카메라 종료, 검토 초안을 입증한다.
- AC-004: 브라우저 증거로 REQ-004의 실제 연속 영상부터 단일 초안, 배정, 자동 기록 방지를 입증한다. 필수 자동 검사와 독립 리뷰를 완료한다.

## 추적성
로컬 카메라·개인정보 결과 → REQ-001 → AC-001. 안정된 단일 캡처 수용 신호 → REQ-002 → AC-002. 사람 검토·플레이어 배정 결과 → REQ-003 → AC-003. 가게 방문 전 검증 결과 → REQ-004 → AC-004.

## 미결정 사항
진행을 막는 결정은 없다. 휴대폰과 가게 성능은 사용자 방문 시 검증한다.
