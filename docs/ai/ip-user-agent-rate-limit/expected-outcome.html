🛡️ EC2 Rate Limiting & User-Agent 방어 체계

단일 t3.micro 인스턴스의 CPU 크레딧과 메모리를 보호하기 위한 2계층 차단 아키텍처

🧑‍💻 정상 인간 브라우저 사용자 HTTP 200 OK
🌐
User-Agent 검사
Mozilla/5.0... Chrome/Safari (화이트리스트 통과)
⏱️
IP 요청 빈도 검사
일반적인 브라우징 (초당 1~2회 요청) ➔ 허용 범위 내
🎯
정상 응답 반환
React SPA 및 정적 파일 즉시 전송 (무마찰 UX 유지)
소모 리소스 정상 (CPU < 2%)
🤖 비인가 AI 에이전트 & 스크레이퍼 HTTP 429 차단
🔍
User-Agent 필터링 (.htaccess)
curl, python, aiohttp, puppeteer 등 감지
⚡
초고속 차단 (Fast Fail)
React 번들이나 무거운 정적 자산 로딩 없이 429 즉각 반환
🛡️
t3.micro 리소스 보호
CPU 크레딧 소모 0에 수렴, 대역폭 및 메모리 절감
차단 지연 시간 < 1ms (Apache 앞단)
⚡ 2차 방어선: IP 기반 빈도 제한 (Apache mod_evasive) IP BURST CONTROL

User-Agent를 위조하여 접근하는 스크레이퍼나 반복 요청 봇이 단기간에 대량 요청을 전송할 경우, IP 단위로 차단합니다.

방어 규칙 임계치 설정 동작 및 영향
페이지별 요청 빈도 (DOSPageCount) 5회 / 1초 단일 URL을 1초에 5회 초과 타격 시 즉시 429 차단
사이트 전체 빈도 (DOSSiteCount) 50회 / 1초 전체 사이트 리소스를 1초에 50회 초과 요청 시 즉시 차단
차단 지속 기간 (DOSBlockingPeriod) 10초 임계치 초과 IP는 10초 동안 모든 요청이 거부됨 (지속 공격 시 연장)
로컬루프백 예외 (DOSWhitelist) 127.0.0.1, ::1 서버 내부 헬스체크 및 관리용 로컬 요청은 절대 차단하지 않음
