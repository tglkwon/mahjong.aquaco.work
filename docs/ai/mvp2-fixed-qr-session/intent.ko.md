## 최초 요청
사용자께서는 다음 주 금요일 대탁(지인 모임) 실전 테스트를 위해, 별도 로그인 없이 자리별 고정 QR을 찍어 1초 만에 착석하고, 점수 인식 테스트 페이지(`/scan_score_test`)에서 점수 확정 시 세션이 종료되며, 사후에 임시 코드와 레거시 설정을 깔끔하게 정리하는 초경량 세션 연동 시스템 구축을 요청하셨습니다:
1. 무인증(Zero-Auth) 및 클라이언트 ID 기반 닉네임 관리: 첫 명시적 등록/착석 시점에만 브라우저 `localStorage`에 지연 발급(Lazy)되는 불변 UUID(`client_id`)를 활용하여 최초 등록 후 다음 판부터는 원클릭(`[⚡ 마작왕(으)로 착석]`) 1초 착석 지원.
2. 기기 등록 정보 초기화 및 좌석 퇴장: `[기기 등록 정보 초기화]` 클릭 시 로컬스토리지 삭제 후 홈 화면(`/`)으로 안전하게 이동하며, 활성 좌석 공석화 및 대기열 `canceled` 처리와 함께 SQLite(`mahjong.db`) 상의 닉네임을 `reset_{epoch}`로 비식별화하여 과거 경기 기록 정합성 보존.
3. 테이블 자리별 고정 QR 스캔 & 매 판(반장) 자리 이동: 테이블 동·남·서·북 좌석에 고정 QR 부착, 매 반장 자리 추첨 후 해당 좌석 QR 스캔, 4인 스캔 완료 시 세션 `active` 자동 승격.
4. 온라인 대기열 (`/queue`): 대기 등록 및 순번/테이블 현황 확인, 대기자 4인 모임 시 입체 마작패(바람패: 동·남·서·북) 디자인의 디지털 자리 뽑기 기능 제공, 빈 좌석 착석 시 `waiting` ➔ `playing` 자동 전환.
5. 정확한 경기 시간 추적: 4번째 착석 시점의 세션 시작 시간(`started_at`), 종료 시간(`finished_at`), 순수 플레이 소요 시간(`duration_seconds`) 정밀 기록.
6. 실시간 점수판 자동 연동: 기록자 화면(`UmaOkaTable.tsx`)에서 2초 주기 Polling으로 착석자 명단을 수신하여 동·남·서·북 드롭다운 자동 채움.
7. 세션 종료 시점 및 점수 인식 테스트 페이지 연동: `/scan_score_test`(`isTestMode={true}`)에서 OCR 검증 후 `[기록 추가 및 공유]` 버튼을 누르는 순간 세션 종료(`finished`), 경기 점수 및 소요 시간 SQLite DB(`mahjong.db`) 저장, 테이블 자동 리셋 및 다음 반장 세션 준비.
8. EC2 인프라 클린 셋업: AWS EC2 `t3.micro`(RAM 1GB) 환경에 최적화된 Node.js Express + `better-sqlite3`(`journal_mode = WAL`) 초경량 백엔드 구축, Apache 리버스 프록시(`/api`) 설정, 과거 잔여물은 `_legacy_backup_2026/`로 격리.
9. 사후 정리 보장: 실전 마작 기록 데이터(`mahjong.db`)는 영구 보존하되, 요청 시 임시 테스트 코드, 레거시 백업, 임시 더미 DB를 일괄 삭제하는 안전한 클린업 스크립트 `cleanup-test-artifacts.sh` 제공.

## 문제와 근거
- 오프라인 마작 모임에서 매 반장마다 `UmaOkaTable.tsx`에 4명의 이름을 수동으로 선택하거나 입력하는 것은 번거롭고 오타가 발생하기 쉬우며 회전율을 떨어뜨립니다.
- 물리적 패를 섞어 자리를 뽑는 과정은 번거롭고 시간이 걸리므로, `/queue` 페이지 내 실감나는 마작패 비주얼의 디지털 자리 뽑기가 오프라인 진행을 대폭 가속합니다.
- 페이지 로드 시 UUID를 즉시 생성하면 초기화 직후 원치 않는 새 식별자가 바로 발급되므로, 등록/착석 버튼 클릭 시 지연 발급하는 것이 필수적입니다.
- 명시적인 `started_at`이 없으면 세션 생성 후 대기 시간까지 경기 시간에 포함되어 순수 한 판(반장) 진행 시간이 왜곡됩니다.
- 지인 모임 특성상 회원가입이나 로그인 절차는 진입 장벽과 불필요한 지연을 초래합니다.
- 점수 인식 기능은 이미 `/scan_score_test`에서 안정적으로 검증되었으므로, 해당 페이지의 최종 기록 확정 버튼 클릭과 백엔드 세션 종료를 직접 결합하면 운영자의 추가 조작이 전혀 필요 없습니다.
- EC2 `t3.micro`는 RAM이 1GB로 매우 제한되어 무거운 DB나 백엔드는 OOM이나 CPU 크레딧 고갈을 유발할 수 있습니다. 경량 Node.js Express + `better-sqlite3` 설정은 100MB 미만의 메모리로 완벽히 작동합니다.

## 원하는 결과
- 플레이어가 좌석 QR을 스캔했을 때 저장된 닉네임으로 1초 만에 원클릭 착석이 완료됩니다.
- 닉네임을 변경하더라도 불변 `client_id`를 기준으로 업데이트되어 이전 기록과 대기열에 일관되게 반영됩니다.
- 기기 등록 정보 초기화 시 로컬 스토리지가 삭제되고 홈(`/`)으로 이동하며, 활성 좌석이 공석화되고 서버 닉네임이 고아 레코드 없이 `reset_{epoch}`로 비식별화됩니다.
- 대기 인원은 `/queue`에서 대기 순번을 확인하고, 4명 대기 시 마작패 타일 형태의 디지털 자리 뽑기를 통해 지정된 좌석을 안내받습니다.
- 4인이 착석을 마치면 세션 시작(`started_at`)이 기록되고 `active` 상태로 승격됩니다.
- 동·남·서·북 4명이 착석을 마치면 `UmaOkaTable.tsx`에 4명의 이름이 자동으로 채워집니다.
- `/scan_score_test`에서 점수 확정 시 세션이 종료되고 점수 및 `duration_seconds`가 `mahjong.db`에 영구 저장되며, 테이블은 즉시 리셋됩니다.
- 대탁 종료 후 필요 시 임시 테스트 도구와 레거시 잔여물을 단 한 번의 명령으로 안전하게 정리할 수 있습니다.

## 제약과 정책
- EC2 `t3.micro` 환경에서 백엔드 메모리 사용량은 150MB 이하로 엄격히 제한.
- `better-sqlite3`는 동시 읽기/쓰기 안전성을 위해 WAL 모드(`journal_mode = WAL`) 및 busy timeout 설정 필수.
- 확정된 경기 기록 데이터(`mahjong.db`)는 절대 유실되어서는 안 됨.
- 서버 오프라인 또는 네트워크 장애 시에도 `/scan_score_test`의 기존 오프라인 수동 기능은 정상 작동해야 함.
- 사용자 승인 없는 파괴적 Git 명령어 또는 DB 삭제 전면 금지.

## 수용 신호
- `/seat?table=1&seat=east` 접속 시 닉네임 입력 후 착석되며, 재접속 시 `[⚡ 마작왕(으)로 착석]` 버튼이 노출된다.
- `[기기 등록 정보 초기화]` 클릭 시 로컬 스토리지가 삭제되고 `/`로 리다이렉트되며, 좌석이 공석화되고 서버 닉네임이 `reset_{epoch}`로 비식별화된다.
- `/queue` 페이지에서 대기열 등록, 순번 확인, 마작패 디자인의 4인 디지털 자리 뽑기 기능이 정상 동작한다.
- 4인이 착석 완료 시 `started_at`이 기록되고 세션이 `active`가 되며 `/scan_score_test`의 `UmaOkaTable.tsx`에 2초 이내로 4명의 닉네임이 자동 반영된다.
- `/scan_score_test`에서 `[기록 추가 및 공유]` 클릭 시 세션이 `finished`로 종료되고 SQLite `mahjong.db`에 `duration_seconds`를 포함한 경기 기록 행이 저장된다.
- 테이블은 즉시 비워져 다음 반장 자리 추첨 후 착석 가능한 상태로 순환된다.

## 가정과 미해결 질문
- 가정: 초기 테이블 수는 1개(Table 1)이며, 스키마는 향후 다중 테이블 확장을 지원하도록 설계합니다.
- 가정: 2초 주기 HTTP Polling은 SQLite WAL 환경에서 EC2 CPU/메모리에 부하를 거의 주지 않습니다.
- 가정: 기록용 모바일/태블릿 단말기는 EC2 서버(`/api`)와 정상 통신 가능한 네트워크에 연결되어 있습니다.

- 아키텍처: `server/` 디렉토리의 Express + `better-sqlite3` 백엔드 및 `src/` 디렉토리의 React 프론트엔드 라우트.
